# KBO 매니저 디자인 · 1차

## 열어보기

`mockup-dashboard.html`, `icons.html`, `badges.html`을 브라우저에서 직접 엽니다. 서버·빌드·네트워크 연결이 필요하지 않습니다. 대시보드에는 같은 폴더의 `tokens.css`, `badges.js`만 필요하며 SVG 심볼은 인라인입니다. 외부 폰트도 사용하지 않습니다.

## 디자인 원칙

- 중계 화면의 방송 그래픽을 감독실까지 확장합니다. 짙은 남색 바탕, 선명한 구획선, 큰 헤드라인, 구단색 상단 밴드, 경기장 곡선을 추상화한 히어로를 사용합니다.
- 정보 우선순위는 다음 경기와 현재 단계 → 감독이 결정할 일 → 순위·재정·소식입니다. 스토브리그에는 개막 전 준비를, 정규시즌에는 시간·대진·예고 선발을 강조합니다.
- 실제 구단 로고·엠블럼·마스코트·워드마크·스폰서 표식은 쓰지 않습니다. 모든 구단은 같은 자체 제작 라운드 배지에 중립 서체 약칭과 색상만 사용합니다.
- 표는 구단·승패·승률·게임차 4열만 유지합니다. `<details>`로 상세 기록을 펼쳐 키보드와 터치 모두 지원합니다. 핵심 기록을 가로 스크롤 뒤에 숨기지 않습니다.
- 이모지 대신 동일한 24px 그리드, 1.75px 선, 둥근 끝점의 SVG를 사용합니다. 아이콘만 있는 버튼에는 통합 시 `aria-label`이 필요하며, 글자와 함께 쓰는 장식 아이콘은 `aria-hidden="true"`로 둡니다.

## 파일과 사용법

| 파일 | 역할 |
| --- | --- |
| `icons.svg` | 탭 10개 + 동작·상태 23개 심볼. ID는 `icons.html`에 표시 |
| `icons.html` | 모든 아이콘 이름과 미리보기 |
| `badges.js` | `teamBadge(teamId, color, size)` → SVG 문자열, `BADGE_TEAMS` 색상표 |
| `badges.html` | `core.js` ROSTERS와 같은 10개 구단 색상 미리보기 |
| `tokens.css` | 간격·곡률·서체·표면·상태·팀 색상 및 컴포넌트 |
| `mockup-dashboard.html` | KIA 정규시즌 화면(실제 게임은 단계에 따라 자동 전환), 할 일 예시 안내, 순위 펼치기 |

```html
<html lang="ko" data-team="한화">
<!-- --team: 원색 / --team-ink: 읽을 수 있는 밝은 강조색
     --on-team: 원색 버튼 위 글자색 -->
```

`--team`은 원색이므로 작은 본문 글자색으로 사용하지 않습니다. `--team-ink`를 강조 텍스트와 선택 표시로 사용합니다. 한화의 밝은 주황 버튼은 어두운 글자를 사용합니다. KT 등 어두운 구단도 밝은 배지 테두리와 텍스트, 버튼 테두리로 경계를 유지합니다. 상태는 색뿐 아니라 ‘대기’, ‘안정’ 등의 텍스트를 동반합니다.

외부 SVG `<use href="icons.svg#play">`는 일부 브라우저의 `file://` 환경에서 차단됩니다. 게임 통합 시 `icons.svg`의 심볼을 문서에 한 번 인라인 삽입하고 `<use href="#play">`로 참조하세요. 프리뷰의 복사본을 수정할 때는 원본 스프라이트와 함께 동기화해야 합니다. 배지 함수는 알려지지 않은 ID를 TEAM으로 표시하고 색상·크기 입력을 제한합니다.

## 후속 통합 매핑 (이번 커밋은 게임 파일 수정 없음)

| 현재 화면/구성 | 새 컴포넌트와 데이터 연결 |
| --- | --- |
| HTML 대시보드의 다음 경기/진행 버튼 | `.hero`, `.hero-top`, `.hero-bottom` / 기존 일정·현재 날짜·단계·선발 데이터 |
| `FM.dashCards0()` 받은 편지함 카드 | `.task-list` / 미해결 actions가 있는 편지 우선, 기존 `FM.openMsg()`로 이동 |
| 캠프 선택과 선수 상태 카드 | 동일 할 일 목록 / 캠프 미결정·부상·휴식 권고를 중복 제거해 표시 |
| `dashCards0()` 이사회·재정 / `feedCard()` | 히어로와 할 일 아래 `.panel` / 기존 계산 결과 그대로 표시 |
| HTML 탭·FM 제목·작전 버튼의 이모지 | 심볼 ID로 매핑 / 탭 `dashboard`~`club`, 작전 `bunt`, `steal`, `intentional-walk` 등 |
| 선수단·계약·기록의 다열 표 | `.stat-table` / 선수·포지션·핵심 기록 등 3~4열, 나머지 `.row-detail`로 이동 |
| `.btn`, `.pill`, `.card`, `.grid` | 신규 CSS를 대시보드 래퍼 아래 한정 적용한 뒤 단계적으로 교체; 전역 충돌 검토 필요 |

단계 문구는 `스토브리그 · 시범경기 · 정규시즌 · 포스트시즌`으로 통일합니다. 시범경기는 실험할 라인업과 선발, 포스트시즌은 시리즈 전적·다음 경기를 히어로에 연결합니다. 목업은 요청한 스토브리그와 정규시즌 두 상태만 구현합니다. 다음 경기가 없으면 대진을 임의 생성하지 말고 ‘일정 미정’ 또는 시즌 종료 안내를 표시해야 합니다.

375px에서는 메뉴가 가로로 스크롤되고 본문은 한 열, 히어로 CTA는 전체 폭입니다. 1280px에서는 좌측 메뉴와 두 열 참고 패널을 사용합니다. 메뉴의 가로 스크롤은 의도된 동작입니다. 날짜·대진·부상·기록·예산은 실제 시즌 사실을 주장하지 않는 가상 게임 예시입니다. 링크와 버튼은 예시 안내만 표시하며 게임 상태를 바꾸지 않습니다.

## 전후 비교

- 같은 무게의 회색 카드 → 경기 히어로, 결정 목록, 낮은 우선순위 참고 패널로 위계 구분
- 빽빽한 다열 표 → 핵심 4열과 행 안의 상세 펼치기
- 제각각인 이모지 → 단일 선형 SVG 체계
- 단일 포인트 구단색 → 헤더 밴드·히어로·선택 행·CTA에 팀 테마 적용

## 검증과 남은 판단

Node로 33개 아이콘 ID의 유일성, 10개 배지 생성, 모든 HTML 인라인 JavaScript 문법을 확인했습니다. 팀별 CTA 글자/배경, 밝은 팀 강조색/상승 표면의 대비를 계산해 WCAG AA 본문 기준 4.5:1 이상인지 확인했습니다. 기본 본문·보조 글자도 같은 기준을 적용했습니다.

브라우저 연결 호스트 오류로 실제 375px·1280px 렌더링 및 키보드 조작은 이번 환경에서 확인하지 못했습니다. 통합 전 두 폭에서 넘침, 긴 선수명, 모든 구단 테마, 확대 200%, 초점 표시를 시각 검수해야 합니다.

프로듀서 확인 항목: 할 일 목록 최대 노출 수(제안 3개 + 전체 보기), 스토브리그에서 미확정 대진을 보일지 여부, 모바일 메뉴를 스크롤 탭으로 유지할지 여부. 목업에서는 3개, 가상 시범경기 대진, 스크롤 메뉴로 제안합니다.

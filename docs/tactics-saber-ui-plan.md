# 작전 야구 · 세이버 · 게임 UI 기획서

작성 2026-11-09. 첫 경기 패치 다음 단계의 기획이다. 코칭스태프 기획서(`coaching-staff-plan.md`)의 코치 구조를 그대로 쓰고, 작전을 코치에 연결한다.

## 지금 코드의 사실

| 항목 | 현재 | 기획에 주는 영향 |
|---|---|---|
| 팀 전술 | 8종: `atk, run, bunt, teamBat, shift, bat, ibb, hook` (`core.js` `DEFAULT_TAC`) | 틀을 유지하고 항목을 늘린다 |
| 경기 중 사인 | 번트·도루·고의4구 (`orderCmd`). 조건이 안 맞는 번트 사인은 남고, 자동 번트가 수동 도루 사인을 지운다 | 신규 사인 전에 유효성·소모 시점·수동 우선순위를 먼저 고친다 |
| 수행도 | `execOf` 0.2~1.05 = 숙련 × 선수 적합도 × 선수단 신뢰 (`fm/05` 78행) | 코치 능력치를 곱할 자리가 여기다. 적합도를 다시 곱하지 않는다 |
| 타석 결과 | `simPA`가 타석 결과를 뽑고, `commitAB`가 실책·병살·희생플라이를 뒤이어 판정한다 | 작전은 네 곳 중 알맞은 자리에 넣는다(1-3) |
| AI 구단 | 기존 8개 방침만 고른다. 숙련·분석도는 사용자 팀에만 전달된다 | 엔진을 공유해도 AI가 새 작전을 저절로 쓰지 않는다 |
| 일정 | 매 경기 상대가 바뀌는 순환전 (`buildSchedule`). 3연전 없음 | 맞춤 전략은 상대 구단별로 저장한다 |
| 경기 기록 | 타석 이력 없이 최근 10경기 요약만 저장. 시즌 말 세이브 약 1MB | 추세·상황 지표 전에 기록 구조와 용량 제한이 필요하다 |
| 투구 내용 | `genPitchSeq`가 **결과가 정해진 뒤** 연출용으로 만든다 | 구종별 성적은 지금은 인과관계가 없는 숫자다 |
| 투타 정보 | 데이터에는 실제 값이 있다(`hand: "우투좌타"`). 엔진은 안 쓰고, 중계 화면은 이름으로 만든 가짜 값을 쓴다(`handB`) | 좌우 상성의 전제 조건. 가장 먼저 고친다 |
| 상대 분석 | 분석도 `scoutKnow`가 삼진·볼넷을 약간 바꾼다 | 맞춤 전략 효과의 상한으로 쓴다 |
| 세이버 지표 | 선수 카드에 wRC+, wOBA, ISO, BABIP, FIP, K/9, BB/9, K-BB% | 지표 자체보다 "관리" 흐름이 비어 있다 |

## 1. 작전 야구

### 1-1. 코치별 작전 소관

작전 하나의 주책임자는 코치 한 명이다. 주책임 코치의 **전술** 능력치만 수행도 배율에 들어가고, 공동 작전도 배율을 겹치지 않는다. 히트앤런과 런앤히트의 주책임자는 주루코치다(코칭스태프 기획서와 일치).

| 담당 | 팀 방침 | 경기 중 사인 | 상태 |
|---|---|---|---|
| 주루코치 | 도루 성향, 추가 진루 성향, 태그업 성향 | 2루 도루, 3루 도루, 더블스틸, 딜레이드 스틸, 히트앤런, 런앤히트, 대주자 | 일부 있음 |
| 타격코치 | 타격 성향(적극·공 보기), 팀배팅, 밀어치기·당겨치기 | 희생번트, 세이프티번트, 버스터, 세이프티 스퀴즈, 수어사이드 스퀴즈, 대타 | 일부 있음 |
| 배터리코치 | 볼배합(정면·유인·몸쪽·바깥쪽·변화구 위주), 견제 빈도, 퀵모션 | 고의4구, 피치아웃, 견제 | 일부 있음 |
| 투수코치·불펜코치 | 교체 타이밍, 좌우 스페셜리스트, 오프너, 마무리 운용 | 투수 교체, 멀티이닝 지시 | 일부 있음 |
| 수비코치 | 내야 시프트(정상·병살·전진), 외야 깊이, 송구 공격성 | 번트 수비, 수비 강화 교체 | 일부 있음 |
| 수석코치 | 전체 작전 빈도(스몰볼 ~ 빅볼) | 벤치 추천: 이번 상황에 맞는 사인 제안 | 신규 |

### 1-2. 수행도 공식

`수행도 = clamp(execOf × 코치 배율, 0.2, 1.05)`, `코치 배율 = 0.9 + 0.2 × (코치 전술 - 1) / 19`

- `execOf`는 이미 숙련, 선수 적합도, 선수단 신뢰를 합친 값이다. 적합도를 따로 곱하지 않는다.
- 코치 배율은 0.9~1.1로 기존 ±10% 원칙을 지킨다. 최종 상한은 지금과 같은 1.05다.
- 작전별 적합도(번트·스퀴즈는 컨택, 도루는 주력, 피치아웃은 포수 어깨)는 `fitOf`에 항목을 추가해 넣는다.

### 1-3. 구현 방식

투구 단위 엔진으로 바꾸지 않는다. 61시즌 QA 기준을 전부 다시 맞춰야 하기 때문이다. 작전은 성격에 따라 네 곳에 넣는다.

| 자리 | 작전 |
|---|---|
| 타석 전 사건 | 2루·3루 도루, 더블스틸, 딜레이드 스틸, 견제. 출발·도착 루, 복수 주자, 3아웃과 득점 순서를 처리한다 |
| 타석을 소비하는 사건 | 희생번트, 세이프티번트, 버스터, 스퀴즈 2종. `_buntCall`을 일반화하고 3루 단독 주자도 허용한다 |
| 타석 수정치(`paMods`) | 타격 성향, 밀어치기·당겨치기, 볼배합 |
| 결과 반영 단계(`commitAB`, `applyOutcome`) | 히트앤런, 런앤히트(삼진 시 도루사, 병살, 안타 후 진루), 추가 진루, 태그업, 팀배팅, 내외야 위치, 송구 공격성, 번트 수비 |

- 교체 계열은 타석 사이 관리 명령이다. `_autoManage`와 재출전 금지 규칙을 함께 고친다.
- 피치아웃은 볼 하나를 대가로, 견제는 투구 수 제외로, 고의4구는 타석 소비로 구분한다.
- **AI·위임 선택기:** 상황을 보고 사인을 고르는 함수를 만들어 AI 구단, 수석코치 위임, 벤치 추천이 함께 쓴다. AI 구단에도 코치 배율과 숙련을 적용한다.
- 사인 규칙: 무효 사인은 즉시 안내 후 소멸, 수동 사인이 자동 작전보다 우선한다.
- 견제 횟수 제한, 수비 시프트 제한 등 KBO 현행 규정은 구현 전에 확인해 반영한다.

### 1-4. 경기 전 맞춤 전략

"경기 준비" 화면에 **전력분석 브리핑**을 넣는다. 지시는 상대 구단별로 저장되어 같은 팀을 다시 만나면 그대로 적용된다.

| 대상 | 지시 항목 | 담당 |
|---|---|---|
| 상대 타자별 | 승부(정면·유인·거르기), 코스(몸쪽·바깥쪽), 수비 위치 | 배터리코치, 수비코치 |
| 상대 투수별 | 공략(초구·공 보기), 노릴 구종, 도루 시도 | 타격코치, 주루코치 |

- 전력분석코치 추천을 **한 번에 적용**할 수 있다. 직접 건드리는 건 선택이다.
- 효과 크기의 상한은 분석도(`scoutKnow`)다. 분석이 없는 상대에게는 지시 효과가 작다.
- 지시가 상대 약점에 맞으면 이득, 강점에 맞서면 손해다. 설정하지 않은 상대에는 수정치가 붙지 않는다(감점도 자동 대행도 없음).

## 2. 세이버메트릭스

### 2-1. 추가할 지표

| 묶음 | 지표 | 조건 |
|---|---|---|
| 가치 | WAR(타자·투수, 구단 내 순위) | 출전량, 수비, 포지션, 대체 수준을 정의한다. 화면에 "근사치"로 표시. 현재 `wrc`는 단순 wOBA 비율이라 보정이 필요 |
| 상황 | 득점권, 주자 유무, 후반 접전 | 결과 반영 전 상태로 집계. 시즌 누적만 저장 |
| 좌우 | 좌투·우투 상대, 좌타·우타 상대 | 투타 실제값 연결 후 |
| 추세 | 최근 10·30경기 흐름, 리그 백분위 | 경기 요약에 HBP, SF, BF를 추가. 개수 제한, 과거 미수집 값은 "자료 없음" |
| 구종 | 구종별 피안타·헛스윙 | 볼배합 지시가 `pickType`과 결과에 연결된 뒤에만 공개 |

타구 속도, 발사각은 엔진에 없는 값이라 넣지 않는다.

### 2-2. 보는 것에서 관리하는 것으로

- **선수 분석 화면:** 핵심 지표를 리그 백분위 막대로, 추세 그래프와 코치 코멘트를 함께 보여 준다.
- **코치 진단:** "BABIP가 본인 기준보다 높습니다", "K-BB%가 3주째 하락" 같은 해석. 일정 표본 미만이면 진단을 내지 않고, 단정 표현을 쓰지 않는다.
- **바로 조치:** 진단 옆에 훈련 과제 지정, 라인업 변경, 휴식 버튼을 붙인다.
- **팀 리포트:** 구단 전체 표. 지표로 정렬하고 필터를 저장한다.

## 3. 게임다운 UI

승인된 `감독실 대시보드 시안`을 기준으로 삼는다. 네이비 바탕, 구단색 포인트, 다음 경기 히어로, "지금 결정할 일" 3개가 뼈대다. 시즌 단계에 따른 화면 변화는 자동이고 전환 탭은 없다.

| 순서 | 내용 |
|---|---|
| 1 | 전역 셸을 시안으로 교체. 기능은 그대로 두고 대시보드·메뉴·공통 색만 바꾼다 |
| 2 | 경기일 흐름: 브리핑 → 라인업 → 작전 → 입장 연출 → 중계 → 결과 |
| 3 | 스쿼드·기록·트레이드 화면을 표 위주에서 선수 카드와 비교 중심으로 정리 |
| 4 | 화면 전환 연출, 시즌 전환 장면(개막, 포스트시즌, 시상식) |

원칙: 외부 파일 의존 없이 패키징 가능해야 한다. 구단 실제 로고는 쓰지 않는다.

## 4. 진행 순서

코덱스 검토를 반영한 순서다. 작전 밸런스는 숙련·컨디션 구조가 바뀐 뒤에 맞춘다.

| 단계 | 내용 | 끝나면 보이는 것 |
|---|---|---|
| A | 공통 스타일을 시안으로 교체(색, 카드, 메뉴, 대시보드) | 게임 전체가 시안 분위기로 바뀜 |
| 기반 | 작전별 QA 집계, 세이브 마이그레이션 틀, 경기 기록 구조와 용량 제한, 사인 버그 수정, 투타 실제값 연결 | 중계 화면의 좌우 표시가 실제 값이 됨 |
| B | 코칭스태프 + 작전 담당 코치 연결 | 코치가 작전 성공에 영향 |
| 캠프 | 캠프와 컨디션(기존 묶음 3) | 숙련 구조 확정 |
| C | 신규 작전: 도루 계열, 히트앤런, 런앤히트, 번트·스퀴즈 계열, 견제, 피치아웃, 번트 수비, 대주자 + AI·위임 선택기 | 경기 중 사인 메뉴 확장 |
| D | 전력분석 브리핑과 맞춤 전략 | 상대별 준비 |
| E | 세이버 2차: WAR, 상황·좌우·추세, 코치 진단과 조치 | 선수 분석 화면 |
| 마감 | 경기일 흐름 전체 통합과 연출, 스토브리그, 뉴스·시상·회고 | 기존 묶음 4~5 |

## 5. 출시 기준

- 작전별 기회·시도·성공·득점 비용을 QA에서 집계하고, 리그 수치가 정해진 범위 안에 있어야 한다. 지금 QA는 전술별 수치를 검사하지 않고, 도루는 경기당 0.82로 실제 0.63보다 많다.
- 중계와 일괄 시뮬레이션의 작전 결과가 같은 분포여야 한다.
- 코치진 최상·최하 비교는 같은 선수·일정, 여러 시드로 하고 수치 기준을 둔다.
- 맞춤 전략을 쓰지 않은 팀에 감점이 없어야 한다.
- 기존 세이브가 깨지지 않아야 한다. 숙련 키, 코치 6→10자리, 능력치 1개→5개, 후보 코치, 전 선수 투타 정보를 채운다.
- 장기 커리어에서 세이브가 실제 저장 한도를 넘지 않아야 한다. 슬롯·백업을 합산해 QA에서 제한을 건다.
- 모든 사인은 경기당 입력 부담을 늘리지 않게 위임 옵션이 있어야 한다.
